# AI Log Triage

A small Python CLI that turns noisy application logs into deterministic, structured diagnostics.

It parses common log levels, groups recurring warnings and errors by normalized signatures, and can optionally send the **aggregate report only** to an OpenAI-compatible LLM endpoint for a concise support summary.

> Built as an independent portfolio project. No proprietary or private project code is included.

## Why this project exists

Production logs often contain the same failure hundreds of times with changing request IDs, IP addresses, UUIDs, or numeric values. That makes manual triage slower than it needs to be.

AI Log Triage first performs deterministic analysis locally, then optionally uses an LLM for a human-readable interpretation.

## Features

- Tolerant parsing for common log levels
- Timestamp extraction when present
- Canonical level normalization (`WARN` → `WARNING`, `FATAL` → `CRITICAL`)
- Signature normalization for volatile values such as:
  - UUIDs
  - IP addresses
  - hexadecimal values
  - numbers
- Recurring warning/error grouping
- Human-readable or JSON output
- Optional AI-assisted summary through an OpenAI-compatible HTTP endpoint
- Raw log lines are **not** sent to the LLM integration
- Zero runtime third-party dependencies
- Unit tests with Python's standard library
- GitHub Actions CI on Python 3.10 and 3.12

## Quick start

```bash
git clone https://github.com/Taynan002/ai-log-triage.git
cd ai-log-triage
python -m pip install -e .
```

Analyze the included example:

```bash
logtriage examples/sample.log
```

JSON output:

```bash
logtriage examples/sample.log --format json
```

Limit the number of recurring signatures:

```bash
logtriage examples/sample.log --top 5
```

## Optional AI-assisted summary

The deterministic analysis works without an AI provider.

To enable `--ai-summary`, configure an endpoint that supports the common `/chat/completions` request shape:

```bash
export LLM_BASE_URL="https://your-provider.example/v1"
export LLM_API_KEY="your-key"
export LLM_MODEL="your-model"

logtriage examples/sample.log --ai-summary
```

On PowerShell:

```powershell
$env:LLM_BASE_URL = "https://your-provider.example/v1"
$env:LLM_API_KEY = "your-key"
$env:LLM_MODEL = "your-model"

logtriage examples/sample.log --ai-summary
```

The integration sends the aggregate diagnostics generated by the local analyzer rather than the original raw log lines.

## Design choices

**Deterministic first.** The useful diagnostics do not depend on an LLM.

**Privacy-aware AI integration.** Only aggregate statistics and normalized signatures are sent when AI summarization is explicitly enabled.

**Low dependency footprint.** The runtime uses the Python standard library, which keeps installation and review straightforward.
